# CodeDNA

CodeDNA is a prototype code-authenticity review tool. It builds a behavioural profile from a developer's historical Python files, then measures whether a new submission is consistent with that history.

It does **not** determine whether code was generated by AI and must not be used as the sole basis for disciplinary action.

## Current milestone

This first runnable slice includes:

- lexical, AST-structural, and complexity feature extraction;
- historical profile construction with means and variance;
- content-hash deduplication and invalid-file handling;
- deterministic component scores, a surface–structure gap, and explainable deviations;
- a lowest-consistency-first file review map for multi-file submissions;
- three-way verdicts: Consistent, Uncertain, and Review Recommended;
- downloadable machine-readable JSON and standalone, print-ready HTML review reports;
- a dependency-free local API and a three-panel browser interface;
- unit and API tests;
- deterministic demo cases.
- safe ZIP ingestion and direct public-GitHub link scanning through commit-pinned repository trees;
- persistent local profiles;
- an offline AST-token representation as a fourth signal;
- a NumPy logistic fusion trainer with held-out-author evaluation;
- a function-level deviation heat map that ranks lexical, structural, and complexity shifts without changing the trained score.
- an error-controlled three-way calibration that reduces false Consistent decisions by routing overlapping cases to Uncertain.

The default fourth signal is a local AST-token representation. An optional frozen CodeBERT provider with function/class chunking and content-hash caching is implemented; see `CODEBERT.md`. Switching providers requires rebuilding profiles and retraining the fusion model.

## Run

Use Python 3.11 or newer:

```powershell
.\start.ps1
```

Then open `http://127.0.0.1:8000/`.

The interface is split into focused pages:

- `/` — product overview and entry points;
- `/analyze.html` — create a fingerprint, add a submission, and generate the review report;
- `/evidence.html` — readiness gates, held-out metrics, method, and limitations.

After a fingerprint is built, add the new submission and select **Analyze consistency**. The report then opens as a separate workflow step. Built-in demos pause briefly on the fingerprint so the transition is readable before the completed report appears.

If Python is not on `PATH`, use the Python executable supplied by your environment.

## API

### `GET /api/health`

Returns service and feature readiness.

### `POST /api/profiles`

```json
{
  "name": "Student A",
  "files": [
    {"name": "history_one.py", "content": "def add(a, b):\n    return a + b\n"}
  ]
}
```

### `POST /api/profiles/{profile_id}/analyze`

```json
{
  "files": [
    {"name": "submission.py", "content": "def subtract(a, b):\n    return a - b\n"}
  ]
}
```

### `GET /api/demo/consistent` and `GET /api/demo/review`

Return deterministic reports produced by the real feature and scoring pipeline.

## Train and evaluate the fusion model

Arrange attributable Python files under one directory per author, with at least four authors and six files each:

```powershell
python -m codedna.collect DATA_MANIFEST_TEMPLATE.csv --dataset work/dataset --manifest work/evaluation/resolved_sources.csv
python -m codedna.evidence work/dataset --output work/evaluation
```

Copy and complete `DATA_MANIFEST_TEMPLATE.csv` first. The collector requires permission/license metadata, resolves each repository reference to a commit SHA and writes a resolved manifest. Then audit the collected folder. The audit flags invalid files, excluded paths and identical content assigned to multiple authors.

The evidence command audits the dataset, refuses an undersized or duplicate-contaminated collection, performs author-held-out model selection, calibrates an uncertainty band and writes a checksum manifest for the complete run. The application automatically loads the trained artifact on the next analysis request. See `EVALUATION.md` and `MODEL_CARD.md` before interpreting its output.

It also generates benchmark and confusion-matrix SVGs, per-fold CSV metrics and evidence Markdown beside `results.json`, so presentation numbers remain tied to the machine-readable evaluation.
